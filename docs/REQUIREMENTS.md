# Требования к системе

## Функциональные требования (FR)

### FR-0: Настройка пользовательского аккаунта Discord (MVP)

**Описание**: Получение и сохранение user token, технических параметров, установка стабильного подключения к Discord Gateway.

**Критерии приёмки**:
- Система успешно подключается к Discord Gateway
- Начинает получать события сообщений
- Токен сохраняется в зашифрованном виде
- Super properties корректно парсятся и сохраняются

**Приоритет**: Критический (блокирующий)

**Версия**: MVP v0.1

---

### FR-1: Ингест Discord (MVP)

**Описание**: Прямое подключение пользовательского аккаунта к Discord Gateway для получения всех сообщений с доступных серверов с последующей фильтрацией по allowlist-каналам; опциональный фильтр по тредам.

**Критерии приёмки**:
- Сообщения из выбранных каналов превращаются в карточки TG
- Сообщения вне allowlist не приходят
- Фильтр по тредам работает корректно (если настроен)
- Обрабатываются все типы текстовых сообщений

**Приоритет**: Критический

**Версия**: MVP v0.1

**Зависимости**: FR-0

---

### FR-2: Ингест Telegram (MVP)

**Описание**: Собирать только личные сообщения (DM) модератору.

**Критерии приёмки**:
- Любой DM модератору создает карточку
- Групповые чаты игнорируются
- Сообщения от ботов обрабатываются (опционально)

**Приоритет**: Критический

**Версия**: MVP v0.1

---

### FR-3: Карточка с контекстом (MVP)

**Описание**: Карточка содержит платформу, (опционально) сервер, канал/тред, автор, время, ~10 последних сообщений контекста; кнопка "Показать больше" без потолка.

**Критерии приёмки**:
- Карточка содержит все обязательные метаданные
- Показывается ~10 сообщений контекста
- Кнопка "Показать больше" догружает батчи истории
- Карточка корректно обновляется при догрузке
- Верхнего лимита на загрузку контекста нет

**Приоритет**: Критический

**Версия**: MVP v0.1

**Формат карточки**:
```
Платформа • [Сервер] • Канал/Тред • Автор • Время

Контекст (последние ~10 сообщений):
...

[Кнопки действий]
```

---

### FR-4: Ответ/подтверждение/постинг (MVP)

**Описание**: Ответ plain text, обязательное подтверждение, постинг 1:1 в исходный канал/DM.

**Критерии приёмки**:
- Без подтверждения сообщение не отправляется
- После подтверждения сообщение доезжает в исходную точку
- Формат: только чистый текст (без Markdown)
- Ответ попадает точно в тот же канал/тред/DM

**Приоритет**: Критический

**Версия**: MVP v0.1

**Поток**:
1. Модератор: "Ответить"
2. Ввод текста
3. Модератор: "Подтвердить"
4. Постинг
5. Статус "Отправлено" или "Ошибка"

---

### FR-5: Медиа (MVP)

**Описание**: Показывать/пересылать изображения; ссылки кликабельные, без превью.

**Критерии приёмки**:
- PNG/JPG отображаются в карточке
- Ссылки кликабельны
- Превью ссылок отключено
- Видео и другие файлы - не приоритет (можно показывать как ссылки)

**Приоритет**: Высокий

**Версия**: MVP v0.1

**Поддерживаемые форматы**:
- Изображения: PNG, JPG, JPEG
- Ссылки: HTTP/HTTPS (кликабельные, без превью)

---

### FR-6: Ошибки/"Повторить" (MVP)

**Описание**: Показывать ошибку + кнопка ретрая (без продуктового backoff).

**Критерии приёмки**:
- При ошибках подключения или отправки видна понятная ошибка
- Кнопка "Повторить" работает и делает повторную попытку
- Нет автоматического backoff (только ручной ретрай)

**Приоритет**: Высокий

**Версия**: MVP v0.1

**Типы ошибок**:
- Ошибки Discord API
- Ошибки Telegram API
- Ошибки подключения к Gateway
- Timeout ошибки

---

### FR-7: DND режим (MVP)

**Описание**: Режим "Не беспокоить" с тумблером и гибким расписанием интервалов.

**Критерии приёмки**:
- При активном DND карточки не приходят модератору
- Сообщения помечаются как muted в БД
- Тумблер вкл/выкл работает мгновенно
- Расписание поддерживает:
  - Интервалы времени (например, 22:00-08:00)
  - Дни недели
  - Множественные интервалы

**Приоритет**: Высокий

**Версия**: MVP v0.1

**Команды**:
- /dnd on - включить
- /dnd off - выключить
- /dnd - открыть диалог настройки расписания

---

### FR-8: LLM варианты/"Смягчить" (v0.2)

**Описание**: Генерация 2 вариантов ответа + кнопка "Ещё варианты"; функция "Смягчить" для перефраза в вежливый тон.

**Критерии приёмки**:
- LLM генерирует минимум 2 варианта ответа
- Варианты учитывают весь доступный контекст
- Кнопка "Ещё варианты" генерирует новые варианты
- Функция "Смягчить" делает текст нейтрально-вежливым
- При низкой уверенности модели - подпись "модель не уверена"
- Все варианты требуют подтверждения перед отправкой

**Приоритет**: Средний

**Версия**: v0.2

**System prompt**: "you are a moderator..."

**Контекст**: вся доступная переписка

---

### FR-9: Напоминания (v0.2, опция)

**Описание**: Напоминания о "висящих" карточках (открытых задачах).

**Критерии приёмки**:
- Функция включается/выключается через настройки
- Напоминание приходит каждые 30 минут
- Максимум 3 напоминания на одну задачу
- DND режим полностью глушит напоминания
- Не спамит модератора

**Приоритет**: Низкий

**Версия**: v0.2

---

### FR-10: Мультисерверность (v1.0)

**Описание**: Пользователь сам выбирает сервера/каналы через команды или диалоги.

**Критерии приёмки**:
- Пользователь управляет allowlist самостоятельно
- Поддержка множественных Discord серверов
- Интерфейс управления через команды /allow_channel, /unallow_channel
- Возможность включения/выключения серверов без удаления из списка

**Приоритет**: Средний

**Версия**: v1.0

---

### FR-11: Редактирование отправленного (v1.0)

**Описание**: Если платформа позволяет - разрешить редактирование; логировать правки.

**Критерии приёмки**:
- Правки отражаются в месте отправки (Discord/Telegram)
- Все правки фиксируются в audit_log
- История правок доступна
- Платформы, не поддерживающие редактирование - показывают предупреждение

**Приоритет**: Низкий

**Версия**: v1.0

**Поддержка**:
- Discord: да (через API)
- Telegram: да (через Bot API)

---

### FR-12: Поиск/Метрики (v1.0)

**Описание**: Базовый поиск по истории; команда /stats для просмотра метрик.

**Критерии приёмки**:
- Поиск работает по:
  - Автору
  - Каналу
  - Тексту (подстрока)
  - Датам (интервал)
- /stats возвращает:
  - Среднее время ответа
  - Нагрузка по каналам
  - Незакрытые задачи >24ч
- Базовый UI для результатов поиска

**Приоритет**: Низкий

**Версия**: v1.0

## Нефункциональные требования (NFR)

### NFR-1: Производительность

**Описание**: Система должна обрабатывать 100-500 событий в сутки со средней задержкой показа карточки < 2-3 секунды.

**Метрики**:
- Пропускная способность: 100-500 событий/сутки
- Latency карточки: < 2-3 сек (от получения события до показа)
- Время ответа API: < 500 мс (p95)
- Время постинга: < 1 сек (p95)

**Версия**: MVP v0.1

---

### NFR-2: Устойчивость

**Описание**: Корректная работа при обрывах соединения с Discord Gateway; автоматический reconnect.

**Требования**:
- Автоматический reconnect к Discord Gateway при обрыве
- Максимальное время восстановления: 30 сек
- Не терять сообщения во время reconnect
- Graceful degradation при недоступности LLM (v0.2+)

**Версия**: MVP v0.1

---

### NFR-3: Наблюдаемость

**Описание**: Детальные логи; алерты в приватный TG-чат админов при ошибках/падениях.

**Требования**:
- Логирование всех операций (уровни: DEBUG, INFO, WARNING, ERROR)
- Структурированные логи (JSON)
- Алерты в TG при:
  - Падениях воркеров
  - Ошибках подключения к Discord Gateway
  - Критических ошибках БД
  - Ошибках постинга (после N неудачных попыток)
- Возможность запроса логов через команду бота

**Версия**: MVP v0.1

---

### NFR-4: Безопасность

**Описание**: TLS; user token и технические параметры шифруются; аудит действий включён.

**Требования**:
- Все внешние соединения через TLS/HTTPS
- User Token Discord: AES-256 шифрование в БД
- Super Properties: шифрование в БД
- Telegram Bot Token: переменная окружения, не в коде
- Аудит всех действий в audit_log:
  - Отправка сообщений
  - Изменение настроек
  - Управление allowlist
  - Редактирование сообщений (v1.0)
- Доступ к боту только для модератора (по Telegram user_id)

**Версия**: MVP v0.1

---

### NFR-5: Хранение данных

**Описание**: Хранение 90 дней; бэкапов нет (осознанное решение).

**Требования**:
- Автоматическая очистка данных старше 90 дней
- Анонимизация/удаление:
  - Текстов сообщений
  - Метаданных
  - Attachments
  - Audit logs
- Бэкапы БД отсутствуют по решению заказчика
- Возможность экспорта данных (опционально, v1.0+)

**Политика очистки**:
- Ежедневный cron job
- Удаление записей старше 90 дней
- Каскадное удаление связанных данных

**Версия**: MVP v0.1

---

### NFR-6: Соответствие ToS

**Описание**: Используется неофициальный метод подключения пользовательского аккаунта к Discord. Осознанное принятие рисков нарушения ToS Discord.

**Риски**:
- Блокировка Discord аккаунта
- Изменения в протоколе Gateway
- Необходимость обновления super properties

**Меры**:
- Резервные аккаунты
- Минимальная активность
- Эмуляция человеческого поведения
- Мониторинг изменений в протоколе

**Версия**: MVP v0.1

**⚠️ ВАЖНО**: Использование на свой страх и риск. Проект может перестать работать при изменении Discord API или ToS.

---

### NFR-7: Масштабируемость

**Описание**: Система должна поддерживать расширение функциональности и рост нагрузки.

**Требования**:
- Модульная архитектура для легкого добавления новых функций
- Возможность горизонтального масштабирования воркеров (v0.2+)
- Поддержка очередей для обработки пиков нагрузки (v0.2+)
- База данных: индексы для производительности при росте данных

**Целевые показатели (v1.0)**:
- До 1000 событий/сутки
- Поддержка 10+ Discord серверов
- Хранение истории до 1 млн сообщений

**Версия**: v0.2+

---

### NFR-8: Доступность (Availability)

**Описание**: Целевой uptime системы.

**Требования**:
- Целевой uptime: 95% (допустимо ~36 часов даунтайма в месяц)
- Graceful shutdown при обновлениях
- Минимизация потери данных при падениях
- Health check endpoints для мониторинга

**Версия**: MVP v0.1

---

### NFR-9: Удобство использования (Usability)

**Описание**: Интерфейс должен быть интуитивным для единственного пользователя.

**Требования**:
- Понятные команды с подсказками
- Понятные сообщения об ошибках
- Минимум кликов для основных действий
- Быстрый доступ к часто используемым функциям
- Команда /help с полным списком возможностей

**Версия**: MVP v0.1

---

### NFR-10: Поддерживаемость (Maintainability)

**Описание**: Код должен быть легко поддерживаемым и расширяемым.

**Требования**:
- Чистая архитектура с разделением слоев
- Документация кода
- Юнит-тесты для критических компонентов
- Интеграционные тесты для основных сценариев
- README с инструкциями по развертыванию
- Версионирование API и схем БД

**Версия**: MVP v0.1

## Ограничения и допущения

### Ограничения
1. Один пользователь (модератор)
2. Только plain text ответы
3. Discord: только пользовательский аккаунт (нарушение ToS)
4. Нет бэкапов БД
5. Хранение только 90 дней

### Допущения
1. Модератор имеет доступ к Discord с правами пользователя
2. Telegram Bot создан заранее
3. Модератор технически подкован для настройки Discord токена
4. Нагрузка не превышает 500 событий/сутки (MVP)
5. LLM API доступен и оплачен (v0.2+)
