# Архитектура системы

## Обзор

Система представляет собой многокомпонентное приложение для агрегации сообщений из Discord и Telegram в единую консоль модератора.

## Основные компоненты

### 1. Discord Ingest Service
**Назначение**: Прием сообщений из Discord через прямое подключение к Gateway

**Функции**:
- Подключение к Discord WebSocket Gateway через пользовательский токен
- Получение событий MESSAGE_CREATE
- Фильтрация по allowlist каналов
- Опциональная фильтрация по тредам
- Нормализация и сохранение в Store

**Технические детали**:
- Использует User Token (не Bot Token)
- Эмулирует поведение официального клиента
- Автоматический reconnect при обрывах
- Парсинг super properties и session ID

**Ключевые риски**:
- Нарушение Discord ToS
- Возможная блокировка аккаунта

### 2. Telegram Ingest Service
**Назначение**: Прием личных сообщений модератору

**Функции**:
- Webhook или Long Polling от Telegram Bot API
- Фильтрация только DM (групповые чаты игнорируются)
- Нормализация и сохранение в Store

**Технические детали**:
- Использует официальный Bot API
- Обработка только private чатов
- Игнорирование групп и каналов

### 3. Message Store & Processing
**Назначение**: Централизованное хранилище сообщений и задач

**Функции**:
- Хранение сообщений с метаданными
- Управление контекстом (история переписки)
- Хранение вложений (изображения, ссылки)
- Управление задачами (tasks)
- Логирование всех действий (audit_log)

**База данных**: PostgreSQL

**Политики**:
- Хранение 90 дней
- Автоматическая очистка старых данных
- Без бэкапов (осознанное решение)

### 4. Telegram Bot (Moderator Console)
**Назначение**: Единый интерфейс для модератора

**Функции**:
- Формирование карточек сообщений
- Прием ответов от модератора
- Обязательное подтверждение перед отправкой
- Управление DND режимом
- Команды настройки и управления
- Показ контекста с пагинацией

**Формат карточки**:
```
Платформа • [Сервер] • Канал/Тред • Автор • Время

[Последние ~10 сообщений контекста]

[Кнопки: Ответить | Показать больше | DND | Повторить]
```

### 5. Discord Poster
**Назначение**: Отправка ответов в Discord

**Функции**:
- Постинг через пользовательское API Discord
- Отправка в исходный канал/тред 1:1
- Обработка ошибок с возможностью ретрая
- Уважение rate limits (v0.2+)

**Технические детали**:
- Использует User Token для постинга
- Эмулирует действия пользователя
- Поддержка тредов и reply-to

### 6. Telegram Poster
**Назначение**: Отправка ответов в Telegram

**Функции**:
- Постинг через Bot API
- Отправка в исходный DM
- Обработка ошибок с возможностью ретрая

### 7. LLM Service (v0.2+)
**Назначение**: Генерация вариантов ответов

**Функции**:
- Генерация 2+ вариантов ответа
- Функция "Смягчить/вежливо"
- Использование полного контекста переписки
- Индикация низкой уверенности

**Технические детали**:
- API: OpenAI или Anthropic Claude
- System prompt: "you are a moderator..."
- Контекст: вся доступная история
- Без фильтрации токсичности

### 8. DND Scheduler
**Назначение**: Управление режимом "Не беспокоить"

**Функции**:
- Ручной тумблер вкл/выкл
- Расписание интервалов (дни недели, время)
- Подавление карточек во время DND
- Пометка сообщений как muted

### 9. Reminder Service (v0.2+)
**Назначение**: Напоминания о висящих карточках

**Функции**:
- Сканирование открытых tasks старше N минут
- Отправка пингов каждые 30 мин
- Максимум 3 напоминания
- Отключается при активном DND

### 10. Queue Manager (v0.2+)
**Назначение**: Управление очередями и rate limits

**Функции**:
- Bucket per-route для Discord API
- Прозрачная обработка лимитов
- Предотвращение блокировок

### 11. Alert Service
**Назначение**: Мониторинг и оповещения

**Функции**:
- Отправка алертов об ошибках в приватный TG-чат админов
- Логирование падений воркеров
- Мониторинг состояния сервисов

## Потоки данных

### Поток 1: Discord → Карточка → Ответ

```
Discord Gateway → Discord Ingest → Message Store
                                        ↓
                                  TG Bot (карточка)
                                        ↓
                            Модератор (ввод ответа)
                                        ↓
                            Подтверждение → Discord Poster → Discord API
                                                    ↓
                                            Update task status
```

### Поток 2: Telegram DM → Карточка → Ответ

```
Telegram User → Telegram Ingest → Message Store
                                        ↓
                                  TG Bot (карточка)
                                        ↓
                            Модератор (ввод ответа)
                                        ↓
                            Подтверждение → Telegram Poster → Telegram API
                                                    ↓
                                            Update task status
```

### Поток 3: LLM варианты (v0.2+)

```
Карточка → Кнопка "Вариант 1/2/Еще"
              ↓
         LLM Service (получение контекста из Store)
              ↓
         Генерация вариантов
              ↓
         Отображение в карточке
              ↓
         Выбор варианта → Подтверждение → Poster
```

### Поток 4: Загрузка контекста

```
Карточка → "Показать больше"
              ↓
         Backend (fetch next batch from Store)
              ↓
         TG Bot обновляет карточку
              ↓
         Повторяется без лимита
```

## Безопасность

### Шифрование
- User Token Discord: AES-256 в БД
- Super Properties: шифрование в БД
- TLS для всех внешних соединений

### Аудит
- Все действия логируются в audit_log
- Фиксация всех отправленных сообщений
- История правок (v1.0+)

### Аутентификация
- Telegram Bot: авторизация по user_id модератора
- Discord: User Token (небезопасный метод по ToS)

## Масштабирование

### Текущие ограничения
- Один модератор (один пользователь)
- Один Discord аккаунт
- Ориентир: 100-500 событий/сутки

### Планы масштабирования (v1.0+)
- Мультисерверность Discord
- Поддержка нескольких модераторов (не в текущей версии)
- Горизонтальное масштабирование воркеров

## Отказоустойчивость

### Reconnection
- Discord Gateway: автоматический reconnect при обрывах
- Telegram: retry с exponential backoff

### Error Handling
- Показ ошибок в карточках
- Кнопка "Повторить" при ошибках постинга
- Алерты в админ-чат при критических сбоях

### Мониторинг
- Логи всех операций
- Алерты при падениях воркеров
- Статус-команды для проверки состояния

## Технологический стек (рекомендуемый)

### Backend
- **Вариант 1**: Python
  - FastAPI / Flask
  - Discord.py-self (для user gateway)
  - python-telegram-bot
  - SQLAlchemy ORM
  - Celery для очередей (v0.2+)

- **Вариант 2**: Node.js
  - Express.js / Fastify
  - discord.js-selfbot-v13
  - node-telegram-bot-api
  - Prisma ORM
  - BullMQ для очередей (v0.2+)

### База данных
- PostgreSQL 14+
- Redis для кеширования и очередей (v0.2+)

### Инфраструктура
- Docker / Docker Compose
- nginx (reverse proxy)

### Мониторинг
- Логи: stdout/stderr → файлы
- Алерты: Telegram Bot API

## Диаграммы последовательностей

### Настройка Discord подключения

```
Модератор → /setup_discord
              ↓
         TG Bot запрашивает User Token
              ↓
         Модератор вводит токен
              ↓
         Backend сохраняет токен (encrypted)
              ↓
         Discord Ingest пробует подключиться
              ↓
         Успех/Ошибка → Модератор
```

### Отправка ответа с подтверждением

```
Карточка в TG Bot
    ↓
Модератор: "Ответить"
    ↓
Ввод текста
    ↓
Модератор: "Подтвердить"
    ↓
Backend → Poster (Discord/Telegram)
    ↓
Постинг в исходный канал/DM
    ↓
Успех → task.status = answered
      или
Ошибка → карточка показывает ошибку + "Повторить"
```

## Принятые архитектурные решения

1. **User Gateway вместо Bot API для Discord**: необходимо для получения всех сообщений, но нарушает ToS
2. **Прямое подключение к Gateway**: избегаем HTTP polling, снижаем latency
3. **PostgreSQL**: реляционная модель для связей между сообщениями, авторами, каналами
4. **Без бэкапов**: осознанное решение заказчика, упрощение инфраструктуры
5. **Единый Telegram Bot**: простота для одного пользователя
6. **Обязательное подтверждение**: предотвращение случайных отправок
7. **90 дней хранения**: баланс между историей и размером БД
8. **Plain text ответы**: простота, совместимость с обеими платформами

## Ограничения архитектуры

1. Один пользователь (модератор)
2. Нарушение Discord ToS
3. Нет горизонтального масштабирования (пока)
4. Нет бэкапов БД
5. Нет полноценной системы авторизации/аутентификации
6. Зависимость от стабильности Discord Gateway
7. Возможность блокировки Discord аккаунта
